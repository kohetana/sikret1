# Роль
Ты работаешь как ИИ-агент внутри учебного проекта. Собери цельную одностраничную рекламную веб-страницу из материалов, которые подготовил студент. 
Сохраняй авторские решения проекта и не подменяй их универсальным шаблоном.

# Перед сборкой
1. Прочитай README.md.
2. Полностью прочитай research.md, era.md, concept.md и sources.md.
3. Найди все Markdown-файлы в blocks/ и прочитай их по порядку числовых префиксов.
4. Просмотри доступные файлы в assets/.
5. Кратко сформулируй:
   - какой объект и какую эпоху представляет проект;
   - кому адресованы вымышленные курсы и что они обещают;
   - какие блоки входят в страницу и в каком порядке;
   - какие конкретные визуальные правила из era.md нужно соблюдать.
После этого переходи к сборке.

# Источники истины
- research.md — исторические факты и ценность объекта;
- era.md — временной диапазон, технологическая и визуальная среда;
- concept.md — аудитория, обещание, голос и центральная шутка;
- blocks/*.md — набор, порядок, содержание и назначение секций;
- sources.md — подтверждения фактов и визуальные ориентиры;
- assets/ — локальные материалы.
Не меняй эти Markdown-файлы без отдельной команды студента.

# Главная задача
Создай готовый index.html. Страница рекламирует вымышленные курсы по объекту исследования так, как это могло бы выглядеть в выбранную эпоху. 
По странице должны считываться историческая ценность объекта, адресат курсов и характер времени.

Используй blocks/*.md как структуру страницы. Сохраняй порядок файлов. Не добавляй новые смысловые секции только ради привычной структуры сайта.
 Если видишь проблему в наборе блоков, кратко сообщи о ней, затем собери страницу по существующим файлам. Можно редактировать фразы ради ритма и цельности. 
Смысл проверенных фактов менять нельзя. Не придумывай даты, цитаты, рейтинги, известных пользователей и события. 
Если для страницы нужен факт, которого нет в подготовленных материалах, оставь нейтральную формулировку или сообщи студенту о пробеле.

Опирайся на era.md и визуальные источники. Используй характерные для периода типографику, плотность, рамки, кнопки, фоны, изображения, композицию и рекламные приёмы. Все секции должны ощущаться частью одной работы. Избегай решений, которые делают страницу похожей на типовой современный сайт и не подтверждаются выбранной эпохой: огромных скругленных карточек, декоративных градиентных пятен, одинаковых сеток преимуществ, чрезмерно пустых экранов и других случайных модных приемов. Юмор должен поддерживать историческую идею и реальные свойства объекта.

# Технический результат
- основной файл — index.html;
- страница открывается локально без сервера и сборки;
- CSS можно разместить внутри index.html;
- JavaScript используй только там, где он нужен концепции;
- локальные изображения подключай относительными путями из assets/;
- внешние библиотеки и сетевые зависимости для просмотра не нужны;
- текст остается читаемым на обычном экране ноутбука;
- никакие элементы не перекрывают основное содержание.

Сопоставь index.html с research.md, era.md, concept.md и каждым файлом blocks/*.md. Проверь, что:
- историческая ценность объекта понятна из страницы;
- выбранная эпоха узнается по нескольким согласованным признакам;
- каждый подготовленный блок присутствует и выполняет свое назначение;
- тексты не содержат выдуманных исторических утверждений;
- визуальная система поддерживает одну рекламную историю;
- index.html открывается локально.
Исправь обнаруженные технические ошибки. Концептуальные решения студента сохраняй.

# Дополнительные ограничения для проекта SQL (1986–1992)
- Все секции должны использовать моноширинные шрифты (Courier, IBM Mono).
- Цветовая схема: зелёный/янтарный на чёрном, синий IBM, белый.
- Никаких скруглённых карточек, градиентов, минимализма.
- Композиция плотная, табличная, с рамками.
- Примеры SQL-кода — в моноширинном блоке, как на терминале.
- Не добавлять современные UI-элементы (тени, анимации, parallax).
- Соблюдать голос эпохи: корпоративный, уверенный, с отсылками к стандартам.

# Центральная шутка
Сквозная шутка проекта: «SQL — это английский. Просто английский, который понимает машина, а не человек.»
Она должна:
- появиться в hero как заявка;
- развернуться в блоке «Что такое SQL» через реальный факт о названии SEQUEL;
- подкрепиться в блоке «История»;
- встроиться в программу курса;
- ожить в истории ученика;
- мягко прозвучать в требованиях;
- замкнуть историю в CTA.
Не превращай шутку в насмешку над SQL. Ключевые достоинства языка остаются настоящими.
